## 1. 工程结构

```
miniprogram/
  app.js / app.json / app.wxss        入口：生成持久 vid、全局状态、API 基址
  config/
    questions.js                      20 题 + 维度/风格词/在意点文案（阶段0移植）
    copy.js                           全部文案 + 动物配置 + 钩子生成（阶段0移植）
  utils/
    score.js                          确定性计分（阶段0移植，同种子同算法）
    api.js                            wx.request 封装，字段契约与阶段0 track.js 一致
  pages/
    index/                            年龄门 → 知情同意
    quiz/                             20 题逐题作答，5 点量表
    result/                           同频占比 + 风格词 + 4 条在意点 + 动物 + 分享 + 预约
```

数据接自有服务器 `stage0-api`（`https://stage0.tongpin.truthhare.com/api`），复用现有 vid 体系与 SQLite。埋点失败静默，不影响答题主流程。

## 4. 身份锚点（已预留，未配置 AppID 时静默降级）

`docs/09` 约定阶段1 用 vid、阶段2 用手机号归并（不静默合并 openid）。openid 只作身份锚点，不参与任何配对或推荐。

- 前端 `app.js` 启动时调 `api.login()`：`wx.login` → code → `POST /api/wx-login`。
- 后端 `POST /api/wx-login { code }` 用 appid+secret 调 `code2session` 换 openid，**加密落库**到 `identities` 表；只回脱敏尾号，`session_key` 绝不返回、绝不落库。
- AppID/Secret 只存服务器环境变量 `TP_WX_APPID` / `TP_WX_SECRET`，绝不进小程序包与 git（**AppID 填在 `project.config.json` 属微信工具必需、非敏感；Secret 绝不进 git**）。
- **当前状态（2026-11-27）**：服务器已配 `TP_WX_APPID=wx2879fb1594869063`，`TP_WX_SECRET` 待用户从微信后台「开发管理 → 开发设置 → AppSecret」获取并告知；缺 Secret 时接口返回 `{"ok":false,"reason":"not_configured"}`，小程序无感降级，不阻断测评与提审。
- 拿到 Secret 后在服务器 systemd 配置里填入 `TP_WX_SECRET` 并 `systemctl daemon-reload && systemctl restart tongpin-stage0` 即生效，无需改代码。

## 5. 已知简化与后续

- **动物形象**：阶段0 用 CC0 SVG 画在分享卡片上；小程序版先只出文字名+俏皮话。原因：小程序包体积与审核友好，且动物不承载结论。若要图形，可后续加本地图片到 `miniprogram/assets/` 并用 `<image>` 引用。
- **分享图**：小程序用 `onShareAppMessage` 原生转发卡片（好奇文案做标题），未做 canvas 长图。原生转发是个人主体唯一稳定的分享路径，符合 `docs/09` 第 3.4 节。
- **生辰/文化彩蛋**：阶段1 未接入（属可选白名单）。避免在个人工具版引入过多数据采集面，降低审核风险。阶段2 正式产品再接。
