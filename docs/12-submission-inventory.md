# 12 · 提审材料清单与填写稿（阶段1 个人主体工具版）

> 用途：微信小程序提审时按此填写《小程序用户隐私保护指引》与个人信息收集清单。
> 口径必须与代码一致；新增字段先改 `docs/08` 第 6.2 节盘点底稿，再改代码，最后同步本文。
> 本文基于 2026-11-27 代码快照，零第三方 SDK、零跨境。

---

## 1. 个人信息收集清单（对应微信后台填写项）

| 收集的信息 | 使用目的 | 使用场景 | 收集方式 | 是否必要 | 单独同意 | 保存期限 | 对应代码 |
|---|---|---|---|---|---|---|---|
| 匿名标识 vid | 串联答题记录与统计 | 首次打开 | 本地自动生成 | 必要 | 否 | 至用户删除 | `app.js` / `track.js` |
| 答题答案、风格画像（同频值/风格词/在意点） | 生成测评结果 | 完成答题 | 用户主动作答 | 必要 | 否 | 至用户删除 | `score.js` / `/api/result`、`/api/profile` |
| 行为事件（页面浏览、答题、分享） | 漏斗统计与产品改进 | 使用全程 | 自动记录匿名事件 | 必要 | 否 | 180 天 | `/api/event` |
| 微信 OpenID | 匿名身份锚点、安全统计 | 小程序登录 | `wx.login` 获取 code 后后端换取 | 非必要 | 否（登录即告知） | 至用户删除 | `/api/wx-login` |
| 出生日期、时辰、性别 | 生成文化彩蛋（日主/生肖/五行） | H5 填写 | 用户主动填写 | 非必要 | **是**（独立勾选） | 至用户删除 | `/api/birth`、加密存 `births` |
| 手机号 | 内测开放通知 | 用户主动预约 | 用户手动输入 | 非必要 | 是（主动提交即同意） | 内测后 30 天 | `/api/reserve` |

**明确不收集（提审时可主动说明，是加分项）**：身份证号、人脸照片/原图、精确地理位置、通讯录、相册、麦克风、摄像头。

**敏感信息**：仅「出生日期/时辰」属敏感个人信息，有单独同意、加密存储、可单独删除、不参与计分与配对。

## 2. 第三方 SDK 清单

**结论：无第三方 SDK。**

| 类别 | 说明 |
|---|---|
| 统计 SDK | 无。漏斗埋点走自有服务器 `/api/event`，不经第三方 |
| 广告 SDK | 无。未接入流量主 |
| 推送 SDK | 无 |
| 支付 SDK | 无。个人主体不提供支付 |
| 登录 SDK | 仅微信官方 `wx.login`（平台能力，非第三方 SDK），只取 code 换 OpenID |
| 地图/定位/录音/摄像头 | 无 |
| 内容审核 SDK | 无（无 UGC） |

全部数据存放在境内自有服务器 `/srv/tongpin-data/`，无跨境传输。

## 3. 微信后台《小程序用户隐私保护指引》填写要点

按上表逐项勾选。几个易错点：

1. **不勾选**「手机号（用于注册/登录）」「微信手机号组件」——我们是用户手动填、仅用于内测通知，不是登录凭证。
2. **不勾选**「相册/摄像头/麦克风/位置」——代码没有这些权限。
3. OpenID 勾"用于账号统计/识别用户"，用途说明写"匿名身份锚点，不用于配对"。
4. 「收集用户信息的目的」统一口径：**传统文化视角的相处风格自测，仅供娱乐参考**。
5. 若后台要求填《隐私政策》链接，填已部署的公开页面 URL（见 `docs/11` 部署记录）。

## 5. 待用户填写项（提交前必须补全）

隐私政策与用户协议中标注 `【待填】` 的两处：

1. **主体名称**：必须与小程序注册主体完全一致（个人姓名或个体工商户名称）。
2. **联系邮箱**：用于接收删除、查询、投诉请求，需真实有效并有人查收。

这两处我无法代填——填错会导致审核驳回或用户权利通道失效。你拿到主体信息后发我，我替换并重新部署。
