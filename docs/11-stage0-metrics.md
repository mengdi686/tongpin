# 11 · 阶段0 运营指标与基线

> 目标是**验证传播**，不是追求好看的数字。所有指标口径固定，不因结果调整定义。
> 拉数据：`python3 scripts/stage0-funnel.py`（本地 SSH 拉线上）；`--local` 在服务器跑；`--file X` 离线分析。
> 令牌从服务器 `/root/tongpin-stats-token.txt` 读，不进 git。

## 1. 指标口径（固定）

| 指标 | 定义 | 事件来源 | 判读 |
|---|---|---|---|
| 访客 | 去重 `vid` 数 | `visitors` 表 | 量级，先看有没有人进来 |
| 年龄门通过率 | `gate_pass / visit` | event | 低=门槛或文案劝退 |
| 测评完成率 | `result_view / gate_pass` | event | 低=题目太长/中途流失 |
| 分享率 | `share_click / result_view` | event | **核心**：结果卡是否有传播欲 |
| 传播闭环 | `ref_in` 次数 | event | >0=分享链接真被点开、归因生效 |
| 预约率 | `reserve_submit / result_view` | event | 是否有留资意愿 |
| 预约数 | `reservations` 表去重 | 表 | 阶段2 触发条件之一 |

样本量 <20 时，比率只作方向参考，不下结论。

## 2. 阶段2 触发条件（写死，不事后放宽）

只有**同时**满足以下三条，才启动婚恋类目办证（企业主体 + ICP）：

1. 预约数 ≥ 100
2. 分享率 ≥ 15%（样本 ≥ 20 次 result_view）
3. 20 份付费意愿访谈中 ≥ 8 份明确愿意付费

任一未达，阶段2 优先级保持低，继续跑阶段0/1 验证。

**判读**（样本极小，仅方向性）：
- ✅ `ref_in=4` 说明分享链接被真实点开并归因成功，传播链路闭环——这是最想验证的事，已验证。
- ⚠️ `visit 17 vs gate_pass 3`：17 次 visit 含本机无头浏览器测试与用户反复刷新，去重访客仅 13；年龄门通过 3 人是真实进入测评的。
- ⚠️ 分享率 100% 是 2 人样本，无统计意义；需攒到 ≥20 份 result_view 再判读。
- ❌ 预约 1/100，远未达阶段2 触发线，婚恋办证继续后置。

## 4. 数据卫生

- 线上数据含真实用户信息，**禁止提交 git**，导出走 `scripts/stage0-export.mjs`。
- 本机无头测试打出的 visit 事件混在真实数据里，判读时注意 `visit` 与去重访客的差。
- 清理测试数据须先备份（`/srv/tongpin-backup-*.tar.gz`），且只删确认的测试 `vid`。
